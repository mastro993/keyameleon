# Settings

Settings is a window with a native preference-style toolbar (`NSToolbar`, `.preference` style) and four panes: **General**, **Keyboards**, **Apps**, and **About**. The window title is always the app name, Keyameleon (Keyameleon (Dev) in Debug builds); the selected toolbar item shows the pane. It reopens on the last pane, and its content has a fixed 620 × 540 size, tall enough for About to fit without scrolling at the default text size; the window does not resize. ⌘, opens the same window; the SwiftUI `Settings` scene exists only because the `App` protocol needs a scene.

- Each toolbar item is a selectable SF Symbol with the pane name. Every pane, including General, uses grouped `Form` and `Section` with the platform margins and row insets. No pane adds per-pane padding.
- **General:** Launch at login (via `SMAppService.mainApp`) as a native toggle in its own `Section`. If a change fails, the toggle shows the real service state and the footer offers **Open Login Items**. A second `Section`, **After an outside change**, offers three rows: **Switch back**, **Until matching keyboard**, and **Until another keyboard**. Each row has a small visual, a title, and one line of explanation; the selected row shows an accent checkmark. The rows are plain buttons with the selected accessibility trait, not a picker. A `?` help icon beside the section heading explains what counts as an outside change. The Keyboards and Apps Input Source selectors remain `PopUpPicker`, an `NSPopUpButton` with the `.flexiblePush` bezel, which keeps the System Settings pop-up box visible at rest; SwiftUI's `Picker` and bordered `Menu` in a grouped `Form` show that box only under the pointer on macOS 26.
- **Keyboards:** the shared keyboard list under an `Input sources` heading. The Input Source control is a `PopUpPicker` in a fixed 176 pt column so every row lines up. An Unavailable Keyboard Assignment reads `Unavailable`, with a tooltip on how to fix it. With no keyboards, a native `ContentUnavailableView` reads `No keyboards detected`, unless saved data is unreadable, in which case only the Retry notice shows.
- **Apps:** one row per App Assignment, mirroring the keyboard rows: app icon, name (with `Not installed` below it when the app is gone), the Input Source `PopUpPicker` in the same 176 pt column without an `Unassigned` choice, and a trailing menu with **Remove**. **Add App…** lists running Dock apps without an App Assignment, then **Choose Other App…**, an open panel at `/Applications`. A new App Assignment starts with the current Input Source. Keyameleon can never be added. With none, a `ContentUnavailableView` reads `No apps` and offers Add App…. A failed read or save shows `Saved apps unavailable` with Retry and disables the controls. Changes save immediately.
- **About:** rows for version (with build number), source code, app data folder, logs folder, license, and updates; the Sparkle acknowledgement; and the creator credit, which scrolls with the pane. Folder paths are selectable and open in Finder. License rows open the bundled `LICENSE.txt` and `Sparkle-LICENSE.txt` and are disabled if the build lacks them.

Guided setup and Settings share `Theme` for colors and type, so the two windows cannot drift. Links use SwiftUI `pointerStyle`, and the menu pill animation is disabled under Reduce Motion.
